### 1. Etapa SEE (Descubrimiento y Audiencia General - TOFU)
- **Definición:** Toda la audiencia que podría consumir el producto o servicio (programadores, emprendedores, diseñadores, empresas que aún no buscan comprar directamente pero necesitan educarse o resolver un problema conceptual).
- **Intención de Búsqueda:** Informacional / Educativa / Conceptos / Diagnóstico de problemas.
- **Keywords y Consultas Típicas:**
  - `¿Qué es hosting NVMe y cómo funciona?`
  - `Diferencias entre servidor Apache vs LiteSpeed`
  - `Por qué mi página web carga lenta en WordPress`
  - `Qué es CloudLinux y para qué sirve el aislamiento de recursos`
  - `Guía para entender certificados SSL HTTPS y TLS`
  - `Puertos y registros DNS: qué son registros A, CNAME, MX`
- **Estructura y Tono del Contenido SEE:**
  1. *Introducción Educativa:* Explicar el concepto de forma clara, amigable y con analogías sencillas.
  2. *Explicación Técnica:* Arquitectura, funcionamiento y diferencias conceptuales (ej. SSD SATA vs NVMe PCIe 4.0).
  3. *Impacto en el Negocio o Proyecto:* Cómo influye en velocidad, SEO en Google y experiencia de usuario.
  4. *Solución / Buenas Prácticas:* Recomendaciones de configuración o infraestructura.
  5. *CTA Suave (Soft CTA):* Enlace sugerido a comparativas de rendimiento o guías de selección de hosting (etapa THINK).

# How the skill works

1. **Inputs**
   - `intentStage` – **Obligatorio:** Fase del funnel de búsqueda (`SEE` | `THINK` | `DO` | `CARE`).
   - `targetKeyword` – **Obligatorio:** Palabra clave principal según la etapa (ej. `mejor hosting arequipa`, `que es hosting nvme`, `comprar hosting peru soles`, `configurar nodejs cpanel`).
   - `title` – Título atractivo y orientado a SEO que responda directamente a la intención elegida.
   - `slug` – Identificador amigable para URL (ej. `mejor-hosting-arequipa-empresas-comparativa`).
   - `excerpt` – Resumen conciso (140-160 caracteres) enfocado en la intención del usuario.
   - `categories` – Lista de categorías (ej. `["Hosting Perú", "Comparativas", "SEO Local", "NodeJS", "WordPress"]`).
   - `tags` – Lista de etiquetas LSI agrupadas de acuerdo a la intención.
   - `region` (Opcional) – Departamento de Perú al que se enfoca el post (`Lima`, `Arequipa`, `Cusco`, etc.).
   - `author` – Nombre del autor (*Heike Developer Hosting*).
   - `coverPrompt` – Prompt en inglés para generar la portada con IA (16:9, estética tecnológica moderna, oscura y representativa).

2. **Paso 0: Sincronización Previa de Main (OBLIGATORIO)**
   Antes de generar imágenes o redactar el post, asegurar que el repositorio esté actualizado con producción:
   ```bash
   git checkout main && git pull origin main
   ```

3. **Paso 1: Generate cover image**
   El skill invoca la herramienta **`generate_image`** con el `coverPrompt` (relación de aspecto 16:9, estética tecnológica moderna, oscura y profesional con toques de color naranja y ámbar corporativos).

3. **Rename & move the image**
   - **Directorio de Imágenes**: `/Users/brayanlaureanopaucar/Proyectos/12 apps/heike-developer-hosting/public/images/blog/`
   - **Nombre**: `<slug>.jpg` (o `<slug>.svg` si es vectorizado).
   - Copiar la imagen generada hacia la ruta final reemplazando archivos previos.

4. **Create the markdown file**
   - **Directorio de Posts**: `/Users/brayanlaureanopaucar/Proyectos/12 apps/heike-developer-hosting/content/blog/`
   - **Ruta del archivo**: `/Users/brayanlaureanopaucar/Proyectos/12 apps/heike-developer-hosting/content/blog/<slug>.md`

   Plantilla de Front-Matter (YAML):

   ```yaml
   ---
   title: "<title>"
   slug: "<slug>"
   date: "YYYY-MM-DD" # OBLIGATORIO: Usar siempre la fecha del día actual (ej. date +%Y-%m-%d)
   excerpt: "<excerpt>"
   coverImage: "/images/blog/<slug>.jpg"
   categories:
     - "Hosting Perú"
     - "Comparativas"
   tags:
     - "hosting <departamento>"
     - "hosting peru"
     - "hosting nvme"
     - "comparativa hosting"
   intentStage: "THINK" # SEE | THINK | DO | CARE
   targetKeyword: "<targetKeyword>"
   author: "Heike Developer Hosting"
   readingTime: "6 min de lectura"
   ---
   ```

   El cuerpo del artículo incluye la estructura correspondiente a la fase (**SEE**, **THINK**, **DO** o **CARE**):
   - Bloque de introducción destacado en blockquote (`> ...`).
   - Imagen de portada (`![Portada](/images/blog/<slug>.jpg)`).
   - Secciones con `##` y `###` que responden al objetivo de la intención de búsqueda.
   - Tabla comparativa vs competidores (en posts THINK / DO).
   - Bloque de código con sintaxis resaltada y explicaciones (en posts CARE / SEE).
   - Bloque de llamado a la acción (CTA) calibrado a la etapa (Soft CTA para SEE, Evaluación para THINK, Hard CTA WhatsApp para DO, Soporte/Upgrade para CARE).

5. **Sincronización con LLMs (llms.txt y llms-full.txt)**
   - Se actualiza `public/llms.txt` y `public/llms-full.txt` con el nuevo artículo para asegurar visibilidad en ChatGPT, Claude, Perplexity y Gemini.

6. **Sincronización con Sitemap (`src/app/sitemap.ts`)**
   - El nuevo post se indexa automáticamente con prioridad `0.8` y frecuencia mensual.

7. **Control de Versiones, Pull Request (Git & PR) y Retorno a Main**
   - Asegurar inicio limpio en main: `git checkout main && git pull origin main`
   - Crear rama: `git checkout -b "feat/blog-<slug>"`
   - Confirmar cambios:
     ```bash
     git add content/blog/<slug>.md public/images/blog/<slug>.jpg public/llms.txt public/llms-full.txt
     git commit -m "feat(blog): publicar <slug> con framework <intentStage> y seo local"
     ```
   - Push al repositorio remoto: `git push -u origin "feat/blog-<slug>"`
   - Crear PR en GitHub:
     ```bash
     gh pr create \
       --title "feat(blog): <title>" \
       --body "## 📝 Nuevo Post: <title>\n\n- **Slug:** \`<slug>\`\n- **Fase:** \`<intentStage>\`\n- **Keyword:** \`<targetKeyword>\`\n- [x] Validado con copy_validator.py\n- [x] Portada 16:9 generada" \
       --base main \
       --head "feat/blog-<slug>"
     ```
   - **RETORNO OBLIGATORIO A MAIN (NUNCA quedarse en la rama del post):**
     `git checkout main`

   **Sincronización Post-Aprobación (Tras merge del PR por el usuario):**
   ```bash
   /root/proyectos/scripts/git_sync_projects.py --pull heike-developer-hosting
   ```
